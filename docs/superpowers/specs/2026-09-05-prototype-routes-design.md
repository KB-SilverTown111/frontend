# 귀편한 금융 프로토타입 화면·라우터 설계

## 목표

Figma `개발초안2`의 하단 `6` 화면군과 사용자 제공 ZIP을 기준으로 온보딩, 송금, 고지서, 생활금융, 공통 음성의 109개 화면 및 `물음표 버튼 화면6` 도움말 화면을 Vue 3 프로젝트에 구현한다. 이번 범위는 화면 표시와 라우터 연결까지이며 API, 실제 금융 실행, 음성 인식, 네이티브 권한 요청은 포함하지 않는다.

## 최적화 원칙

- 110개 화면을 개별 Vue 파일로 만들지 않는다.
- 화면 구조는 공통 렌더러 1개와 화면 데이터로 분리한다.
- 화면 데이터는 온보딩, 송금, 고지서, 생활금융, 음성의 5개 모듈로 나누고 현재 흐름만 동적으로 불러온다.
- 공통 모바일 셸, 디자인 토큰, 화면 패턴 CSS는 한 번만 로드한다.
- 기존 shadcn-vue 컴포넌트와 `PretendardVariable.woff2`를 재사용하며 새 패키지를 추가하지 않는다.
- 기존 디자인 시스템 소개 화면은 별도 라우트로 보존한다.

## 라우트 구조

- `/` → `/prototype`
- `/prototype` → 전체 흐름과 화면을 탐색하는 인덱스
- `/prototype/:flow/:screenId` → 공통 화면 렌더러
- `/prototype/help` → `물음표 버튼 화면6`
- `/design-system` → 기존 `App.vue` 디자인 시스템 소개 화면

`flow`는 `onboarding`, `transfer`, `bills`, `living`, `voice`만 허용한다. 존재하지 않는 흐름이나 화면은 프로토타입 인덱스로 돌아갈 수 있는 안내 상태를 보여준다.

## 컴포넌트 구조

- `App.vue`: 전역 `RouterView`만 담당한다.
- `DesignSystemView.vue`: 기존 디자인 시스템 소개 화면을 이동해 보존한다.
- `PrototypeIndexView.vue`: 5개 흐름과 110개 화면으로 이동하는 카탈로그를 제공한다.
- `PrototypeScreenView.vue`: 라우트 매개변수에 맞는 흐름 데이터를 지연 로딩하고 화면을 렌더링한다.
- `MobileScreenShell.vue`: 390px 기준 상단 상태 영역, 브랜드, 뒤로 가기, 도움말, 하단 메뉴를 담당한다.
- `ScreenContent.vue`: 제목, 설명, 카드, 선택지, 입력, 금액, 알림, 진행 상태, 음성 패널 등 반복 패턴을 렌더링한다.
- `prototypeFlows.js`: 흐름 메타데이터와 동적 import 로더만 포함한다.
- `data/prototype/*.js`: 화면별 문구와 상태 데이터를 흐름 단위로 보관한다.

기존 `Button`, `Card`, `Input`, `Alert`, `Badge`, `Progress`, `VoiceAssistPanel`은 그대로 우선 재사용하고, 화면 접근성 또는 상태 표현에 필요한 최소한의 variant만 추가한다.

## 화면 데이터와 이동

각 화면 데이터는 `id`, `title`, `description`, `content`, `primaryAction`, `secondaryAction`, `tabs`를 가진다. 공통 렌더러는 타입별 콘텐츠를 기존 UI 컴포넌트로 변환한다.

- 도움말 버튼은 항상 `/prototype/help`로 이동한다.
- 뒤로 가기는 브라우저 이력이 있으면 이전 화면, 없으면 프로토타입 인덱스로 이동한다.
- 기본 주요 버튼은 같은 흐름의 다음 화면으로 이동한다.
- 하단 메뉴는 홈, 고지서, 생활금융 각 흐름의 첫 화면으로 이동한다.
- 프로토타입 인덱스에서 모든 화면에 직접 접근할 수 있어 분기 화면도 빠짐없이 확인할 수 있다.

이번 단계는 라우터 시연용이므로 실제 송금·납부 버튼은 서버 요청을 보내지 않는다.

## 디자인 시스템

- 글꼴: `/public/fonts/PretendardVariable.woff2`, 가변 굵기 100–900
- 색상: 기존 `globals.css`의 background, foreground, primary, accent, destructive, border 토큰
- 터치 영역: 주요 버튼 최소 56px, 아이콘 버튼 최소 48px
- 반경: 기존 shadcn 토큰을 사용하고 모바일 카드만 필요한 범위에서 확대
- 상태: 성공, 경고, 오류는 색상 외에 아이콘과 문구를 함께 표시
- 화면 폭: 모바일에서는 전체 폭, 넓은 화면에서는 390px 기기 프레임으로 중앙 정렬

## 오류 처리

- 잘못된 라우트 매개변수는 빈 화면 대신 안내 카드와 인덱스 이동 버튼을 보여준다.
- 흐름 데이터 로딩 중에는 진행 상태를 보여준다.
- 흐름 데이터 로딩 실패 시 재시도와 인덱스 이동을 제공한다.
- 구현 범위 밖의 금융·권한 동작은 실행하지 않고 명확한 프로토타입 상태로 유지한다.

## 검증

- 화면 데이터 총계가 110개인지 검증한다.
- 각 화면 ID가 중복되지 않고 라우트에서 해석되는지 검증한다.
- 다섯 흐름 첫 화면, 도움말, 존재하지 않는 화면을 브라우저에서 확인한다.
- 키보드 포커스, 버튼 이름, 390px 모바일 폭과 데스크톱 중앙 정렬을 확인한다.
- `npm run lint`, `npm run format:check`, `npm run build`를 실행한다.
